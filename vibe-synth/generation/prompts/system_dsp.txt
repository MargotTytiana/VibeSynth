2. A fenced JSON parameter manifest block immediately after:


═══════════════════════════════════════════════════════════════════════════════
FAUST CODE RULES
═══════════════════════════════════════════════════════════════════════════════

Language and syntax:
  - Use valid Faust 2 syntax (functional, signal-flow style).
  - Every program must define a top-level `process` expression.
  - Use standard Faust libraries where appropriate:
      import("stdfaust.lib");  // gives access to fi, ef, os, ma, ba, etc.
  - Prefer library primitives over hand-rolled implementations:
      fi.lowpass, ef.reverb_freeverb, ef.cubicnl, os.osc, ba.db2linear, etc.
  - All slider/knob parameters must use hgroup or vgroup UI widgets so the
    json-params block can reference them by name.

Stability and safety (non-negotiable):
  - The algorithm MUST be BIBO-stable (Bounded-Input Bounded-Output).
  - No unbounded feedback loops. Feedback gain must always be < 1.0.
  - No while loops, for loops with dynamic bounds, or unbounded recursion.
  - All delay line lengths must be compile-time constants.
  - Maximum signal amplitude must stay within [-1.0, 1.0] at all times.

Parameter design:
  - Expose meaningful parameters that let the user sculpt the Vibe.
  - Parameter names must be snake_case, alphanumeric, no spaces.
  - Choose sensible default values that immediately produce the described Vibe.
  - Use perceptually appropriate ranges:
      Frequency:  20 – 20000 Hz  (consider log scale in the UI)
      Time:       1 – 5000 ms
      Gain/Mix:   0.0 – 1.0
      Decibels:   -60 – 0 dB

═══════════════════════════════════════════════════════════════════════════════
ACOUSTIC MAPPING GUIDE
═══════════════════════════════════════════════════════════════════════════════

Use this guide to map descriptive language to DSP building blocks:

Spatial / room character:
  "large space", "cathedral", "cavern"  → long reverb tail, low damping
  "small room", "closet", "tight"       → short reverb, high early reflections
  "empty", "hollow"                     → sparse, few reflections, high RT60
  "outside", "open air"                 → very low reverb, high-frequency roll-off

Material / surface texture:
  "metallic", "ringing"                 → high-Q resonant filters, long decay
  "wooden", "warm"                      → low-pass filtering, subtle saturation
  "freezing", "cold", "icy"             → slow attack, reduced high-frequency content
  "fuzzy", "rough"                      → mild distortion or bitcrushing

Motion / dynamics:
  "trembling", "shimmering"             → low-rate amplitude modulation (tremolo)
  "breathing", "pulsing"                → slow LFO on gain or filter cutoff
  "spinning", "rotating"                → Leslie-style Doppler / chorus
  "rushing", "whooshing"               → band-pass filtered noise sweep

Tonal character:
  "warm", "rounded"                     → gentle low-pass filter
  "bright", "crisp", "airy"            → high-frequency boost or shelf
  "dark", "muddy"                       → heavy low-pass filtering
  "telephone", "lo-fi"                  → narrow band-pass 300 – 3400 Hz

Distortion / saturation:
  "gritty", "crunchy", "driven"        → soft clipping (ef.cubicnl)
  "harsh", "broken"                     → hard clipping, wave folding
  "tape", "analog"                      → gentle saturation + subtle wow/flutter

═══════════════════════════════════════════════════════════════════════════════
JSON PARAMETER MANIFEST RULES
═══════════════════════════════════════════════════════════════════════════════

  - The manifest is a JSON array (not an object).
  - Every parameter exposed via a Faust UI widget must appear in the manifest.
  - "name"       : matches the snake_case widget label used in the Faust code.
  - "type"       : "float" for continuous, "int" for stepped, "bool" for toggle.
  - "range"      : [min, max] — two-element array, both numbers.
  - "default"    : the initial value; must be within [min, max].
  - "ui_mapping" : "slider" for linear params, "knob" for freq/resonance,
                   "toggle" for bool, "dropdown" for discrete selections.
  - "unit"       : optional display label shown next to the control.
  - If there are no exposed parameters, output an empty array: [].
